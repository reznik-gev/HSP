# 0089 — The floor editor (frontend phase 3)

- **Date:** 2026-10-15
- **Status:** Accepted
- **Refines:** [0016](0016-2026-10-08-edit-concurrency.md), [0042](0042-2026-10-08-2d-renderer.md)–[0052](0052-2026-10-08-svg-commitment-and-performance-gate.md), [0081](0081-2026-10-10-drafts-and-changesets.md), [0082](0082-2026-10-10-publish-discard-restore.md), [0086](0086-2026-10-12-automatic-release.md), [0087](0087-2026-10-13-frontend-delivery-plan.md)

## Note on how this was decided
> Choices 1–3 are the product owner's. The layout and the edge-case details below were **chosen by the assistant**: the owner asked not to design every piece up front, and to change things later once the editor can be used. Treat them as **lower-confidence**. Where the assistant is genuinely unsure about a UI choice during the work, it asks the owner first rather than deciding alone.

## Context
Phases 1 and 2 (the viewer and the admin screens, [0087](0087-2026-10-13-frontend-delivery-plan.md), [0088](0088-2026-10-14-admin-screens.md)) are merged. The editor's behaviour is already decided in [0042](0042-2026-10-08-2d-renderer.md)–[0052](0052-2026-10-08-svg-commitment-and-performance-gate.md), and the backend for editing is complete: the edit lock ([0016](0016-2026-10-08-edit-concurrency.md)), drafts and changesets ([0081](0081-2026-10-10-drafts-and-changesets.md)), and publish, discard and restore ([0082](0082-2026-10-10-publish-discard-restore.md)). The built-in catalog is seeded ([0021](0021-2026-10-08-object-catalog.md)), so real furniture can be placed before a Catalog screen exists. The frontend already has the editor core from the SVG spike ([0052](0052-2026-10-08-svg-commitment-and-performance-gate.md)): pan and zoom, hit-testing, selection, dragging and wall joins, but no drawing tools, saving or panels.

The goal of phase 3: **an admin can draw a real office floor from scratch, label its seats and publish it.** Assigning the seats then works as in phase 2.

## Decisions
| # | Question | Options | Chosen |
|---|---|---|---|
| 1 | Split and order | **Draw → speed → 3D** / draw → 3D → speed / Catalog screen first | **3a, drawing:** everything needed to draw and publish a floor. **3b, speed:** the tools that make it fast. **3c:** the 3D view and the Catalog screen. Each sub-phase is usable on its own. |
| 2 | Entering the editor | **Own full-screen page** / edit mode on the floor page / a separate tab | **`/floors/:id/edit`**, opened by **Edit floor** on the floor page (admins only). Opening it takes the edit lock; **Exit** releases it. The app sidebar folds away to give the plan room. |
| 3 | Saving | **Autosave** / Save button / autosave plus named checkpoints | **Autosave** about 1 second after the last change, batched into one changeset. The top bar shows *Saving…* / *Saved*. Exiting keeps the draft for next time; viewers see the published plan until **Publish**. |

## Layout (assistant's choice)
- **Top bar:** the floor name and draft state ("Draft 4 · Saved"), Undo and Redo, **Publish**, **Discard draft** and **Exit**.
- **Tool strip** on the start side (left in English, right in Hebrew): Select `V`, Wall `W`, Door `D`, Window `N`, Column `C`, Zone `Z`, Place item `P`. `Esc` returns to Select.
- **Panel** on the end side, with two tabs:
  - **Properties** of the selection, with numeric fields ([0045](0045-2026-10-08-dimension-entry.md)) and "mixed" for differing values in a multi-selection.
  - **Problems:** errors and warnings; clicking one selects its element.
- **Place item** shows a searchable catalog list by category in the same panel.
- The plan never mirrors ([0087](0087-2026-10-13-frontend-delivery-plan.md) choice 6); only the bars and panels do.

## Edge cases (assistant's choice, following [0016](0016-2026-10-08-edit-concurrency.md), [0081](0081-2026-10-10-drafts-and-changesets.md), [0082](0082-2026-10-10-publish-discard-restore.md), [0086](0086-2026-10-12-automatic-release.md))
- **Someone else is editing:** Edit floor is disabled with "Being edited by Dana since 09:12". Admins also get **Take over**, which force-releases the lock; the other person's draft is kept.
- **The lock is lost** (heartbeat failed, or someone took over): editing stops at once and a message says why. Unsaved changes stay in the browser; **Retry** takes the lock back and sends them.
- **Stale revision** (`409 stale-revision`): the editor reloads the draft and says so. With the lock this should be rare.
- **The server rejects a changeset:** the change is undone locally, its element is highlighted, and the error appears in Problems with the server's code ([0037](0037-2026-10-08-api-errors.md)).
- **Publish** opens a dialog with what changed (added, moved, removed; from the diff API, [0080](0080-2026-10-10-plan-read-access-and-diff.md)). When assigned seats would disappear it names them and asks to confirm (`unassign_seats`, [0082](0082-2026-10-10-publish-discard-restore.md)). Nothing else asks "Are you sure?".
- **Discard draft** acts at once ([0086](0086-2026-10-12-automatic-release.md)); the notice offers Undo, which restores the draft from its last revision.

## Phase 3 PR sequence (stacked, [0079](0079-2026-10-08-stacked-pr-workflow.md))
**3a, drawing:**
1. This record, and the **editor page**: the route, Edit floor, the lock (acquire, heartbeat, release, take over) and the top bar.
2. The **edit store**: operations with their inverses, undo and redo ([0050](0050-2026-10-08-undo-redo.md)), and autosave of changesets.
3. **Walls:** the polyline wall tool, joins, dragging junctions ([0044](0044-2026-10-08-wall-joins.md)).
4. **Doors, windows and columns.**
5. **Zones:** drawing polygons and choosing the zone type.
6. **Placing items:** the catalog picker, placing and rotating, and the seat label and allocation mode for desks.
7. The **Properties** panel.
8. Server errors in the **Problems** panel.
9. **Publish, Discard** and a version history list with **Restore**, plus a Playwright flow: draw a room, place a desk, publish.

**3b, speed:** snapping ([0047](0047-2026-10-08-snapping.md)); typed measurements at the cursor and on-plan dimensions ([0045](0045-2026-10-08-dimension-entry.md)); arrays and auto-numbering, then copy and paste between floors ([0049](0049-2026-10-08-bulk-layout-tools.md)); live in-browser checks using the shared cases ([0051](0051-2026-10-08-validation-feedback.md)).

**3c:** the 3D view with the 2D / 3D / Split modes ([0043](0043-2026-10-08-editor-view-layout.md)), and a **Catalog** screen for custom items ([0083](0083-2026-10-10-catalog-and-device-api.md)).

3b and 3c get their PR lists when 3a is merged.

## Testing
- The editor core (tools, operations, undo, snapping) gets plain unit tests, with no DOM ([0052](0052-2026-10-08-svg-commitment-and-performance-gate.md)).
- Screens get component tests against the fake API, in both languages ([0087](0087-2026-10-13-frontend-delivery-plan.md)).
- One Playwright flow at the end of 3a; the SVG performance check ([0074](0074-2026-10-08-svg-gate-results-and-v1-bounds.md)) keeps running.

## Consequences
- The editor core grows from the spike's code in `frontend/src/editor/core`; the SVG view stays thin.
- Every editor string needs English and Hebrew ([0087](0087-2026-10-13-frontend-delivery-plan.md)); the owner reviews wording with the rest of the UI.
- Until 3b, drawing has only a fixed grid snap and typed values in the Properties panel, so 3a floors are drawn more slowly but just as precisely.
