# 0050 — Undo/redo: per editing session

- **Date:** 2026-10-08
- **Status:** Accepted

## Options considered
- **Session undo** ✅
- Persistent undo stored server-side

## Decision
- Undo/redo history is **unlimited within the current editing session**: from acquiring the floor lock until releasing it.
- Every user action is recorded as a list of plan operations plus their **inverses**, using the same model as changesets ([0036](0036-2026-10-08-floor-plan-io.md)).
- Undo applies the inverse operations locally and queues them for autosave. Undoing past an autosave works the same way, because the server simply receives the inverse operations.
- Shortcuts: `Ctrl+Z` / `Ctrl+Shift+Z` (`Ctrl+Y`).

## Consequences
- History resets when the lock is released or force-released, or the page is reloaded. Older states come from the version history, and discarding the draft is still possible ([0015](0015-2026-10-08-floor-plan-versioning.md)).
- The operation/inverse design must be complete for every operation type, including cascades (a wall deleted with its openings). This is covered by property-based tests: applying ops and then their inverses must give back the original plan.
