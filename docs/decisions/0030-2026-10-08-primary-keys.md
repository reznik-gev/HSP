# 0030 — Primary keys: UUIDv7

- **Date:** 2026-10-08
- **Status:** Accepted

## Options considered
- **UUIDv7** ✅
- bigint identity
- bigint internally + UUID public

## Decision
All entity tables use **UUIDv7** primary keys (`uuid` type). IDs are generated in the application, so services know an ID before insert. This matters for building outbox events and audit records in one transaction.

## Consequences
- IDs are globally unique, which supports future multi-tenancy ([0003](0003-2026-10-07-tenancy-model.md)), CSV import upserts ([0027](0027-2026-10-08-v1-interim-people-and-access.md)) and merging environments.
- Time ordering keeps B-tree inserts mostly append-only, so index performance is close to bigint.
- IDs are not human-friendly. User-facing labels (seat codes like `3-B-12`, asset tags) are separate, tenant-unique fields.
- Pure association tables (e.g. memberships) may use composite keys instead.
- Revision rows ([0028](0028-2026-10-08-floor-version-storage.md)) also get UUIDv7 IDs, because diffs and audit entries reference them.
