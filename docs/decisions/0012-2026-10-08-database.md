# 0012 — Database: PostgreSQL + PostGIS

- **Date:** 2026-10-08
- **Status:** Accepted

## Context
HSP stores organizational data, cm-precise geometry and time-slotted bookings, and it runs on-prem.

## Options considered
- **PostgreSQL + PostGIS** ✅
- Microsoft SQL Server: on-prem licensing cost, weaker async Python drivers.
- MySQL / MariaDB: weaker spatial and constraint support.

## Decision
Use **PostgreSQL** with the **PostGIS** extension as the single primary database.

## Consequences
- Spatial queries (which zone contains this desk, overlap and clearance checks, distances) run in the database with GiST indexes. This offsets Python's CPU limits ([0010](0010-2026-10-08-backend-stack.md)).
- Geometry is stored in a **local metric coordinate system per floor**, not geographic coordinates. Integer millimetres from [0004](0004-2026-10-07-space-authoring-model.md) remain the canonical values in the domain and API.
- Booking overlaps are prevented with an **exclusion constraint** (`btree_gist`, `tstzrange`) per seat ([0009](0009-2026-10-07-seat-assignment-model.md)).
- OpenFGA ([0013](0013-2026-10-08-rebac-engine.md)) uses the same Postgres server, with a separate database/schema, so operators run one database engine.
- Backup and restore is standard `pg_dump` / PITR and is documented for operators.
