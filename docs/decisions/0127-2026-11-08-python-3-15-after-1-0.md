# 0127 — Python 3.15 waits until after 1.0.0

- **Date:** 2026-11-08
- **Status:** Accepted
- **Relates to:** [0091](0091-2026-10-15-python-3-14.md) (Python 3.14 everywhere), [0059](0059-2026-10-08-supply-chain-security.md) (Dependabot)

## Context
Dependabot opened #136, which moves only the backend image to `python:3.15-slim`. Its `images` job fails: the backend requires Python 3.14 (`requires-python = ">=3.14,<3.15"`), so uv finds no matching Python in the image. [0091](0091-2026-10-15-python-3-14.md) says the Python version moves everywhere at once: both images, `requires-python`, `.python-version`, ruff, mypy and the lock files, in `backend/` and `backup/`. A Dependabot PR that changes one image can never pass.

The options:
- **Move to 3.15 now, everywhere.** The first release would ship on the newest Python. But 3.15 is only weeks old, our packages with compiled parts (asyncpg, Shapely, cryptography, pydantic) may not all support it yet, and it's a risky change right before 1.0.0.
- **Stay on 3.14 for now, and move later as a planned change.**

## Decision
The owner's choice: **stay on Python 3.14 for 1.0.0.** #136 is closed. Dependabot no longer offers Python's minor versions for the backend image (an `ignore` rule in `.github/dependabot.yml`). It still offers new images within 3.14. The move to 3.15 comes after 1.0.0, as its own change with its own record, covering everything 0091 lists.

## Consequences
- No more Dependabot PRs for a new Python version. Someone has to start the move to 3.15. When it starts, the `ignore` rule comes out in the same change.
