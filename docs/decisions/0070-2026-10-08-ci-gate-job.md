# 0070 — CI structure: single workflow with a gate job

- **Date:** 2026-10-08
- **Status:** Accepted
- **Refines:** [0053](0053-2026-10-08-code-hosting-and-ci.md) (replaces the separate path-filtered `backend` and `frontend` workflows)

## Context
The `main` ruleset requires status checks ([0064](0064-2026-10-08-branching-workflow.md)). Two problems surfaced:
1. Both original workflows named their job `check`, so GitHub showed two indistinguishable checks named "check". Neither could be required specifically.
2. Path filters at the workflow level mean a docs-only PR (a common case, since decision records are frequent) never runs the workflows. The required checks would never report, and the PR could **never be merged**.

## Options considered
- **Single workflow with a gate job** ✅
- Always run both workflows (remove path filters) and require both
- Keep path filters with no required checks

## Decision
`.github/workflows/ci.yml` runs on every push to `main` and every PR:

| Job | Runs when | Purpose |
|---|---|---|
| `changes` | always | Detects which areas changed ([`dorny/paths-filter`](https://github.com/dorny/paths-filter)) |
| `backend` | backend, shared or CI files changed | Everything from 0053's backend workflow |
| `frontend` | frontend, shared, `backend/openapi.json` or CI files changed | Everything from 0053's frontend workflow |
| `ci-ok` | always | **The only required check.** Fails if any job failed or was cancelled. Passes if they succeeded or were skipped. |

## Consequences
- Docs-only PRs get a green `ci-ok` within seconds and stay mergeable.
- New CI jobs (e.g. the performance budget from [0052](0052-2026-10-08-svg-commitment-and-performance-gate.md), deploy config validation) are added to `ci-ok`'s `needs` and are enforced **without touching the ruleset**.
- Scheduled and release workflows from 0053 (`perf` nightly, `backup-restore` weekly, `release` on tags) remain separate workflows. They don't gate PRs.
