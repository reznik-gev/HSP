# 0103 — A live demo with a made-up company, and a script

- **Date:** 2026-10-19
- **Status:** Accepted

## Context
The owner wants to show HSP to a friend who is going to be a client, before v1 is complete. The plan from 2026-10-18 listed "a demo document, feature by feature" as its last item. Nothing existed for it. An old seed script from 2026-10-12 predated the frontend and lived outside the repo.

## Options considered
The owner chose each of these:

| Question | Options | Chosen | Why |
|---|---|---|---|
| Format | **Live, plus a guide** / a document only / the friend installs it | **Live, plus a guide** | Seeing HSP run makes the strongest impression. The guide doubles as the feature-by-feature document, and both can be reused for later clients. Installing it themselves is all by hand until `bin/hsp`. |
| Language | Hebrew first / **English first, Hebrew shown** / Hebrew only | **English first, then switch to Hebrew** | The demo company and its people are in English, and switching shows the right-to-left layout. |

## Decision
- **`deploy/demo/seed.py`** builds **Northwind Robotics**: 44 people in 12 teams, Tel Aviv HQ (Harbor Tower, floors 3–5) and Haifa Lab.
  - **Through HSP's own API,** signed in through Keycloak like a browser, so every rule applies: the org chart from a CSV and an Excel import, three drawn floors, devices, and seats.
  - **Each seat state appears:** assigned, reserved for a team, free, bookable and unavailable.
  - **Floor 3 has two published versions.** Floor 4 has a draft left open. Floor 5 is added but not drawn.
  - **Devices:** some on desks, some issued to people, some spare.
- **Its own database, `hsp_demo`,** rebuilt from scratch on every run, so each demo starts the same. The seed refuses to go on if the API isn't on `hsp_demo`, so a development database is never filled.
- **Two sign-in accounts in the dev realm,** matching people in the company: `dana.levin` (office manager, admin) and `sam.carter` (an engineer), both with the password `demo`. They exist only in the dev Keycloak.
- **[`docs/demos/northwind-robotics.md`](../demos/northwind-robotics.md)** has the setup and a 20-minute script: what to click, what to say, and honest answers about what isn't in v1 yet. `deploy/demo/new-hires.csv` is for showing an import.

My lower-confidence choices:
- **The dev stack, not the production bundle.** It runs on the owner's Windows machine with the tools already used every day, and the seed resets it in a minute. The production stack is Linux-first, so on Docker Desktop it needs changes to its data folder.
- The company, its names, its floors and the script's order.
- Screenshots in the guide, taken from the seeded demo, so the page also works as a document to send.

## Consequences
- The demo is only as current as `seed.py`. A change to the API or the plan rules can break it. Running the seed shows that at once, because it stops at the first refused request.
- The guide's screenshots age as the UI changes. Retake them when a screen changes noticeably.
- No new behaviour in HSP itself, so there's no changelog entry.
