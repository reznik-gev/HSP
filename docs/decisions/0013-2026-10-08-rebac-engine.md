# 0013 — ReBAC engine: OpenFGA

- **Date:** 2026-10-08
- **Status:** Accepted
- **Refines:** [0007](0007-2026-10-07-authorization-model.md)

## Options considered
- **OpenFGA** ✅: CNCF project, simple DSL, Postgres-backed, official async Python SDK, lightweight.
- SpiceDB: richer schema and caveats, but heavier to operate.
- Custom in-app ReBAC: no extra service, but we would own correctness and performance.

## Decision
Use **OpenFGA**, self-hosted, backed by the shared PostgreSQL ([0012](0012-2026-10-08-database.md)).

## Consequences
- The authorization model from 0007 is written in the OpenFGA DSL and versioned in the repo, with model tests (`fga model test`) run in CI.
- One OpenFGA store per tenant (a single store in v1) keeps tenant isolation ([0003](0003-2026-10-07-tenancy-model.md)).
- The app writes relationship tuples through a transactional outbox, so the app DB and OpenFGA never diverge permanently.
- "List objects the user can edit" (for example, to filter a floor-plan view) uses OpenFGA `ListObjects`. Its performance is benchmarked early.
- Conditional permissions (for example, time-based ones) can use OpenFGA conditions if they're needed later.
