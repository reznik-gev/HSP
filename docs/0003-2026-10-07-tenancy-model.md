# 0003 — Tenancy: single organization now, SaaS-ready

- **Date:** 2026-10-07
- **Status:** Accepted

## Context
HSM could be an internal tool for one organization or a multi-tenant SaaS product.

## Options considered
- **Internal, single org:** simplest, fastest to ship.
- **Multi-tenant SaaS:** needs tenant isolation, onboarding and billing hooks from day one.
- **Single org now, SaaS-ready** ✅: ships for one org without blocking multi-tenancy later.

## Decision
Ship for a single organization, but don't make assumptions that block multi-tenancy.

## Consequences
- Every tenant-owned table and authorization object carries a `tenant_id` from the start. Version 1 always has exactly one tenant.
- No global singletons for configuration. Settings are stored per tenant.
- Tenant-aware query scoping is enforced in the data-access layer, not in individual handlers.
- Billing, self-service onboarding and per-tenant IdP realms are deferred.
