# 0035 — API style: REST + OpenAPI, versioned under /api/v1

- **Date:** 2026-10-08
- **Status:** Accepted

## Options considered
**Style:**
- **REST + OpenAPI** ✅
- GraphQL (Strawberry)
- REST for writes + a GraphQL read layer

**Versioning:**
- **URL prefix `/api/v1`** ✅
- No versioning (internal API only)
- Header-based

## Decision
- The API is a **resource-oriented REST API** described by the **OpenAPI** schema that FastAPI generates.
- **Workflows are explicit command endpoints** (`POST …/publish`, `POST …/lock`), not hidden state changes behind `PATCH`.
- All endpoints live under **`/api/v1`**. A breaking change introduces `/api/v2`, which runs alongside v1 for a documented deprecation window. Additive changes (new fields, new endpoints) stay within v1.
- The OpenAPI schema is exported in CI to `backend/openapi.json`, and the TypeScript client is generated from it ([0039](0039-2026-10-08-frontend-api-client.md)).

## Conventions
- JSON with `snake_case` fields. Lengths are integer **mm**, rotation is integer **decidegrees** ([0029](0029-2026-10-08-geometry-representation.md)). Timestamps are ISO 8601 UTC.
- Geometry is sent as compact coordinate arrays (`[[x,y],…]`), not GeoJSON. Coordinates are local mm and not geographic, so GeoJSON's WGS84 semantics would be misleading.
- IDs are UUIDv7 strings ([0030](0030-2026-10-08-primary-keys.md)). Clients **may supply IDs for new elements** in changesets, so the editor can reference new elements before the server responds.
- Errors use Problem Details ([0037](0037-2026-10-08-api-errors.md)). Lists use cursors ([0040](0040-2026-10-08-pagination.md)).

## Resource outline (v1)
```
/api/v1
  /auth/login · /auth/callback · /auth/logout · /auth/me        (BFF, 0038)
  /sites · /sites/{id}
  /buildings · /buildings/{id}
  /floors · /floors/{id}
    /floors/{id}/versions                     list history
    /floors/{id}/versions/{n}                 full plan of version n   (0036)
    /floors/{id}/versions/{a}/diff/{b}        diff between versions
    /floors/{id}/draft                        GET full draft plan · POST create draft · DELETE discard
    /floors/{id}/draft/changesets             POST batch of operations (0036)
    /floors/{id}/draft/publish                POST (returns conflicts or the new version)
    /floors/{id}/draft/restore/{n}            POST draft from historical version
    /floors/{id}/lock                         GET status · POST acquire/heartbeat · DELETE release
    /floors/{id}/lock/force-release           POST (admin)
  /zone-types · /catalog-items · /catalog-items/{id}/revisions
  /devices · /devices/{id}                    search by asset tag
  /org-units · /people · /positions
  /imports                                    POST CSV/XLSX upload, GET result report (0027)
  /seat-assignments                           GET (filter by seat/person/unit) · PUT /seats/{element_id}/assignment · DELETE
  /search?q=                                  "where does X sit", asset tag, seat label
  /audit-events                               admin
```

## Consequences
- One schema system: Pydantic models produce OpenAPI, which produces TS types.
- Complex UI reads (for example a floor with its seat holders) are served by purpose-built endpoints that embed the data, instead of GraphQL.
- Future connectors (HRIS/CRM, [0002](0002-2026-10-07-build-approach.md)) get a stable, documented, versioned contract.
