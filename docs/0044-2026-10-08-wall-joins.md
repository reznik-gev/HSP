# 0044 — Wall joins: linked endpoints in the editor

- **Date:** 2026-10-08
- **Status:** Accepted
- **Keeps:** the [0029](0029-2026-10-08-geometry-representation.md) / [0034](0034-2026-10-08-v1-data-model.md) wall representation unchanged

## Options considered
- **Linked endpoints** ✅
- Explicit wall-node graph (data model change)
- Independent segments

## Decision
- Walls remain independent **2-point segments** in storage.
- The editor builds a **virtual junction graph** on load and after each change. Endpoints that are **exactly equal** (integer mm) form a junction. An endpoint lying exactly on another wall's centreline forms a T-junction.
- **Drawing:** the polyline wall tool chains segments, so each new segment starts at the previous end. Snapping to existing endpoints and centrelines ([0047](0047-2026-10-08-snapping.md)) creates junctions.
- **Editing:** dragging a junction moves every connected endpoint, producing one changeset that updates several walls ([0036](0036-2026-10-08-floor-plan-io.md)). Alt-drag detaches a single endpoint.
- **Rendering:** L-corners get mitred joins and T-junctions get butt joins, in both 2D and 3D. The join geometry is computed for display only and never stored.

## Consequences
- No data-model or versioning change.
- "Enclosed area" detection (for example, offering to create a room zone from a wall loop) can run on the virtual graph. That's a nice-to-have, not v1.
- Junctions depend on exact equality, so imports and paste must keep integer coordinates. They do by construction.
