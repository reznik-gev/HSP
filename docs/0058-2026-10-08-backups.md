# 0058 — Backups: built-in scheduled dumps

- **Date:** 2026-10-08
- **Status:** Accepted

## Options considered
- **Built-in scheduled dumps** ✅
- Point-in-time recovery with pgBackRest
- The customer's responsibility

## Decision
- A `backup` service runs a **nightly `pg_dump`** (custom format, compressed) of the **HSP** and **Keycloak** databases, plus the OpenFGA database once it exists ([0013](0013-2026-10-08-rebac-engine.md)), together with the deployment's config files (`.env` secrets are excluded unless explicitly enabled).
- Retention defaults to **7 daily + 4 weekly** and is configurable.
- Targets: a mounted volume or path (local disk, NFS, SMB), or an **S3-compatible** endpoint (e.g. on-prem MinIO).
- Operator commands:
  - `hsp backup now`
  - `hsp backup list`
  - `hsp restore <backup>` restores into a stopped stack after confirmation.
- The same mechanism produces the pre-upgrade backup ([0056](0056-2026-10-08-upgrades-and-migrations.md)).
- **Restore drill in CI**, weekly ([0053](0053-2026-10-08-code-hosting-and-ci.md)): seed data → backup → restore into a fresh stack → verify row counts and a smoke test.

## Consequences
- RPO is up to 24 h. Continuous WAL archiving (PITR) can be added later without replacing this.
- Backup freshness is exposed as a metric with an alert ([0057](0057-2026-10-08-observability.md)).
- The dumps contain personal data (names, emails, seat locations), so encrypting the backup target is documented as the operator's responsibility. Optional dump encryption with a configured key may be added.
