# 0042 — 2D editor rendering: SVG

- **Date:** 2026-10-08
- **Status:** Accepted

## Options considered
| Option | Notes |
|---|---|
| Konva (react-konva) | Canvas scene graph with built-in hit-testing, drag and transform handles. |
| **SVG (React DOM)** ✅ | Crisp at any zoom, styled with CSS, easy to debug in devtools, accessible. Interactions are hand-built. |
| Three.js orthographic (R3F) | Shares one scene with 3D, but 2D annotations and editor ergonomics are harder. |
| PixiJS (WebGL) | High-throughput, but low-level for editor interactions. |

## Decision
The 2D plan editor renders with **SVG** through React components.
- Pan and zoom by changing the root `viewBox`. The SVG user unit is **1 mm**, matching storage ([0029](0029-2026-10-08-geometry-representation.md)).
- Y axis: plan +Y points up (north), so a single root transform `scale(1,-1)` flips it. Text is counter-flipped.
- Interaction (select, drag, rotate handles, snapping, rubber-band selection) is implemented in an editor layer that sits above the render layer.

## Risks and mitigations
SVG performance degrades at around 1–2k interactive DOM nodes, and some office floors approach that size.
- **Layering:** static content (unselected walls, zones, objects) renders in memoized groups that don't re-render while dragging. Only the selection and active handles update per frame.
- **Drag preview** is applied as a `transform` on a single group, not by re-rendering each element. Updates commit on pointer-up.
- **Level of detail:** at low zoom, object details (chair shapes, labels) are hidden or simplified.
- **Pointer events** are disabled on non-interactive decoration. Hit-testing uses simple outline shapes.
- **Performance budget:** a CI-run benchmark with a synthetic 3,000-element floor must keep dragging at ≥ 50 fps on reference hardware. If SVG can't meet the budget, a later decision moves the static layer to `<canvas>` while keeping SVG for interaction.

## Consequences
- Plans can be exported as SVG or printed directly (a nice by-product).
- Editor interactions are custom code. This is the largest frontend effort in v1.
