# 0037 — API errors: RFC 9457 Problem Details

- **Date:** 2026-10-08
- **Status:** Accepted

## Options considered
- **RFC 9457 Problem Details** ✅
- FastAPI default `{detail}` + custom codes

## Decision
Every error response is `application/problem+json`:
```json
{
  "type": "https://hsm.example/problems/changeset-invalid",
  "title": "Changeset violates floor invariants",
  "status": 422,
  "detail": "2 operations failed validation.",
  "instance": "/api/v1/floors/…/draft/changesets",
  "request_id": "…",
  "errors": [
    { "code": "opening_exceeds_wall", "op_index": 0, "element_id": "…", "message": "Door ends 120 mm past the wall end." },
    { "code": "zone_partial_overlap", "op_index": 3, "element_id": "…", "related_ids": ["…"], "message": "…" }
  ]
}
```
- The `type` URIs are stable identifiers, documented under `docs/api/problems.md` once the API exists. They don't need to resolve in on-prem installs.
- FastAPI request-validation errors are converted into the same shape (`type: …/request-invalid`, with `errors[].pointer` as a JSON Pointer to the bad field).
- Each `errors[].code` is a stable machine code that the frontend maps to localized messages and to element highlighting in the editor.

## Status code conventions
| Status | Use |
|---|---|
| 400 | Malformed request |
| 401 / 403 | Not authenticated / not allowed |
| 404 | Not found, or not visible to the caller |
| 409 | Stale `base_revision`, lock held by someone else, publish conflicts |
| 422 | Domain or invariant validation failed |
| 423 | Floor locked (explicitly signals lock state to the editor) |

## Consequences
- Validation errors and domain errors look the same to clients.
- `request_id` ties an error to logs and to audit events ([0033](0033-2026-10-08-audit-logging.md)).
