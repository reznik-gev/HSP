# 0036 — Floor-plan I/O: load the whole plan, save atomic changesets

- **Date:** 2026-10-08
- **Status:** Accepted
- **Builds on:** [0016](0016-2026-10-08-edit-concurrency.md), [0028](0028-2026-10-08-floor-version-storage.md)

## Options considered
- **Load whole, save changesets** ✅
- Load whole, save whole (the server diffs)
- Per-element CRUD

## Decision
### Load
`GET /floors/{id}/versions/{n}` and `GET /floors/{id}/draft` return the **complete plan** of that version in one payload:
```json
{
  "floor_id": "…", "version": 13, "state": "draft", "revision": 42,
  "walls":    [{ "id": "…", "a": [0,0], "b": [12000,0], "thickness_mm": 150, "height_mm": 2800 }],
  "openings": [{ "id": "…", "wall_id": "…", "type": "door", "offset_mm": 900, "width_mm": 900, "height_mm": 2100, "sill_mm": 0, "swing": "left_in" }],
  "columns":  [ … ], "zones": [ … ],
  "objects":  [{ "id": "…", "catalog_item_rev_id": "…", "position": [3200,1500,0], "rotation_ddeg": 900, "label": "3-B-12", "allocation_mode": "assigned", "device_id": null, "attached_to": null }],
  "catalog":  { "<catalog_item_rev_id>": { "shape": "box", "width_mm": 1600, … } }
}
```
The catalog revisions the plan uses are embedded, so the editor can render without extra requests.

### Save
`POST /floors/{id}/draft/changesets`:
```json
{
  "base_revision": 42,
  "ops": [
    { "op": "add",    "kind": "wall",   "id": "<client uuidv7>", "data": { … } },
    { "op": "update", "kind": "object", "id": "…", "data": { "position": [3300,1500,0] } },
    { "op": "delete", "kind": "opening", "id": "…" }
  ]
}
```
- Every operation applies **in one transaction**. If any invariant fails ([0034](0034-2026-10-08-v1-data-model.md)), the whole changeset is rejected with a Problem Details response that lists each failing operation and element.
- **Draft revision counter:** each accepted changeset increments `revision`. A changeset whose `base_revision` doesn't match the current revision is rejected with `409`. This is a safety net behind the edit lock.
- Only the **current lock holder** may post changesets ([0016](0016-2026-10-08-edit-concurrency.md)).
- `update` sends **only the changed fields** (merge semantics). Deleting a wall cascades to its openings, and the response reports the cascaded deletions.
- The response returns the new `revision` and any **warnings** (non-blocking checks such as a desk inside a door swing).

## Consequences
- The editor keeps a local operation queue and **autosaves** it every few seconds or on blur. The same operation model can drive client-side undo/redo.
- Multi-element edits (moving a wall with its doors, rotating a desk cluster) are atomic.
- The draft revision counter is separate from version numbers: versions change on publish, revisions on every save.
- Payload size: a 2,000-element floor is roughly 0.5–1 MB of JSON, which gzip compression handles. A per-zone partial load can be added later if it's ever needed.
